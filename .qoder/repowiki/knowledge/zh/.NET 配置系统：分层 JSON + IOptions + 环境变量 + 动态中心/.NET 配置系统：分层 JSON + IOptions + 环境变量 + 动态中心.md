## 1. 使用的系统与框架
- 基于 .NET 内置的 `Microsoft.Extensions.Configuration` 体系，通过 `WebApplication.CreateBuilder(args)` 自动加载 `appsettings.json`、`appsettings.{Environment}.json` 以及环境变量。
- 使用 `IConfiguration` + `IOptions<T>` / `IOptionsSnapshot<T>` / `IOptionsMonitor<T>` 进行强类型配置绑定与热更新。
- 通过 `Serilog.Settings.Configuration` 将 Serilog 与配置系统打通，实现日志级别、输出目标等由配置文件驱动。
- 在技能（Skills）层面引入 AgileConfig 作为分布式配置中心示例，支持实时推送与灰度发布。

## 2. 关键文件与位置
- 根级应用配置入口与默认配置：
  - `appsettings.json`：集中存放 Kestrel、JWT、CSP、安全头、健康检查、Metrics、Tracing、认证策略、各数据库连接串、Redis/MemoryCache/Session、ReverseProxy 等大量示例配置键。
  - `mvp/appsettings.json`：MVP 示例的最小化 appsettings，仅包含 Logging 基础设置。
- MVP 项目的模块化配置目录：
  - `mvp/Configurations/*.json`：按功能拆分 database.json、cache.json、logger.json、security.json、signalr.json、minio.json、nacos.json、quartz.json、hangfire.json、openapi.json、zipkin.json 等，体现“按领域拆分 JSON”的组织方式。
- Options 与绑定演示：
  - `mvp/Options.cs`：定义 DatabaseOptions、EmailServiceOptions、CacheOptions、SecurityOptions 等强类型选项类，配合 `[Required]`、`[Range]`、`[EmailAddress]` 等 DataAnnotations 验证；展示 `IOptions<T>`、`IOptionsSnapshot<T>`、`IOptionsMonitor<T>` 三种访问模式，以及 `IConfigureOptions<T>` 后处理、`IOptionsChangeTokenSource<T>` 变更监听、`IValidateOptions<T>` 生成器校验等完整生命周期。
- 服务发现与配置热更新：
  - `code/service_discovery_integration.cs`、`code/service_discovery_advanced_integration.cs`：注册 `IConfigurationChangeListener`，结合 ServiceDiscovery 的 `Providers = ["dns", "configuration", "kubernetes"]` 与 `RefreshInterval` 实现配置与服务发现的联动。
- 技能层配置元数据：
  - `skills/agileconfig/index.yaml`：AgileConfig 技能的元数据描述，说明该技能用于“分布式系统配置管理、实时配置推送、灰度发布、配置版本管理”。
- 其他辅助配置：
  - `.gitignore` 中忽略 `.env`，表明环境变量是敏感配置的主要来源之一。
  - `mvp/.dockerignore` 忽略 `secrets.dev.yaml`、`values.dev.yaml` 等开发密钥文件。

## 3. 架构与约定
- 分层加载顺序遵循 .NET 默认约定：`appsettings.json` → `appsettings.{Environment}.json` → 环境变量 → 命令行参数。MVP 项目进一步把配置拆分为多个 `Configurations/*.json`，通过代码或宿主初始化时按需合并。
- 强类型优先：所有可配置项都映射为 POCO 选项类，并通过 DataAnnotations 做启动期校验，避免运行时隐式错误。
- 热更新能力：对需要运行时调整的配置（如缓存、邮件、数据库重试策略），使用 `IOptionsMonitor<T>.OnChange` 订阅变更并执行重连/重建逻辑；同时提供 `ConfigurationChangeListener<T>` 封装 `IOptionsChangeTokenSource<T>`。
- 环境隔离：通过 `ASPNETCORE_ENVIRONMENT` 区分 Development/Staging/Production，并在选项中根据环境设置默认值（例如开发环境关闭重试）。
- 外部化与加密：提供 `IConfigurationEncryptionService` 接口及模拟实现，支持以 `enc:` 前缀标记密文字段，在绑定后统一解密。
- 健康检查集成：通过 `IHealthCheck` 暴露配置健康状态（如连接字符串缺失、SMTP Host 缺失等），便于运维探测。

## 4. 约定与约束
- 配置源组织约定
  - 根级 `appsettings.json` 主要用于示例聚合与通用开关（Kestrel、安全头、CSP、鉴权策略、反向代理等）。
  - MVP 项目中每个子系统独立一个 `Configurations/*.json`，保持单一职责与可维护性。
- 强类型绑定与验证
  - 所有配置必须对应明确的 Options 类，并使用 `[Required]`、`[Range]` 等特性约束取值范围；复杂场景通过 `IConfigureOptions<T>` 做后处理，通过 `IValidateOptions<T>`（源码生成）做结构化校验。
- 热更新与监听
  - 对需要运行时生效的配置，必须通过 `IOptionsMonitor<T>` 订阅 `OnChange`，并在回调中完成资源重建（连接池刷新、客户端重建等）。
- 环境变量与敏感信息
  - 敏感配置（连接串、密钥）应通过环境变量注入，`.env` 文件被 `.gitignore` 排除，禁止提交到仓库。
- 服务发现与配置联动
  - 服务发现配置通过 `ServiceDiscoveryOptions.Providers` 声明支持的解析器（dns/configuration/kubernetes），并通过 `RefreshInterval` 控制刷新频率；同时注册 `IConfigurationChangeListener` 以便在配置变化时触发相应动作。
- 日志配置分离
  - `logger.json` 单独管理 Serilog 与 Microsoft Logging 的级别、SensitiveData 掩码、WriteTo 目标（Console/File/Seq/Elasticsearch/MySQL）等，与业务配置解耦。

总体而言，该仓库采用 .NET 标准配置体系（Configuration + Options）作为核心，辅以多 JSON 文件拆分、环境变量覆盖、可选的 AgileConfig 分布式中心，以及完善的强类型验证与热更新机制，形成一套可扩展、可观测、可演进的配置系统范式。
