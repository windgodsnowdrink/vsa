# IOC 技能参考文档

## 概述

本文档提供了 IOC 技能的详细参考信息，包括技术架构、API 参考、性能优化和最佳实践等内容。本技能基于 .NET 10 开发，支持 AOT 编译，提供了高性能的依赖注入功能。

## 技术架构

### 核心组件

1. **Program 类**：命令行入口点，负责解析命令和参数
2. **IocContainer 类**：核心容器类，实现服务注册、解析和管理
3. **IocSettings 类**：配置选项类，管理容器配置
4. **BenchmarkResult 类**：基准测试结果类，用于返回测试结果

### 架构特点

- **模块化设计**：清晰的职责分离，便于维护和扩展
- **依赖注入**：使用依赖注入模式，提高代码可测试性
- **异步编程**：使用 async/await 模式，提高并发性能
- **配置管理**：使用强类型配置选项，便于管理配置
- **错误处理**：完善的错误处理和日志记录

## 性能优化

### AOT 编译

AOT（Ahead-of-Time）编译是本技能的核心性能优化策略，它将 C# 代码在构建时编译为机器码，而不是在运行时通过 JIT（Just-in-Time）编译。

#### AOT 编译优势

1. **启动速度快**：消除了 JIT 编译的开销，程序启动更快
2. **内存占用低**：减少了运行时的内存使用，特别是对于大型应用
3. **部署简单**：生成单个可执行文件，无需额外依赖
4. **安全性高**：减少了运行时攻击面，提高了安全性

### 内存优化

1. **服务生命周期管理**：根据服务特性选择合适的生命周期
2. **依赖注入**：使用依赖注入减少不必要的对象创建
3. **资源释放**：实现 IDisposable 接口，及时释放资源
4. **缓存机制**：对于频繁使用的服务，考虑使用缓存

### 并发优化

1. **异步编程**：使用 async/await 模式，提高并发性能
2. **线程安全**：确保容器操作线程安全
3. **并行处理**：对于批量注册和解析操作，考虑使用并行处理

### 解析优化

1. **服务解析缓存**：缓存已解析的服务，提高重复解析性能
2. **依赖图优化**：优化依赖解析算法，减少解析时间
3. **批量注册**：对于多个服务，使用批量注册减少容器构建时间

## 最佳实践

### 服务注册

1. **接口优先**：优先注册接口和实现类，而不是具体类
2. **生命周期选择**：根据服务特性选择合适的生命周期
   - **Transient**：轻量级、无状态服务
   - **Scoped**：每个请求需要单独实例的服务
   - **Singleton**：重量级、有状态服务
3. **批量注册**：对于多个相关服务，考虑使用批量注册
4. **命名服务**：对于同一接口的多个实现，考虑使用命名服务

### 服务解析

1. **构造函数注入**：优先使用构造函数注入，而不是属性注入
2. **依赖最小化**：减少服务依赖，避免过度依赖
3. **接口隔离**：使用接口隔离原则，减少服务之间的耦合
4. **延迟解析**：对于大型依赖图，考虑使用延迟解析

### 配置管理

1. **强类型配置**：使用强类型配置选项，便于管理配置
2. **环境变量**：通过环境变量覆盖默认配置，便于不同环境部署
3. **配置验证**：验证配置值的有效性，避免运行时错误
4. **配置文档**：为配置选项提供详细文档，便于使用

### 错误处理

1. **异常处理**：妥善处理服务注册和解析过程中的异常
2. **错误信息**：提供清晰的错误信息，便于调试
3. **日志记录**：记录详细的日志，便于问题排查
4. **重试机制**：对于临时故障，考虑使用重试机制

## 故障排除

### 常见问题

#### 1. 程序无法启动

**可能原因**：
- 缺少 .NET 10 运行时（非自包含发布）
- 操作系统版本不兼容
- 权限不足

**解决方案**：
- 安装 .NET 10 运行时
- 使用兼容的操作系统
- 以管理员权限运行

#### 2. 服务注册失败

**可能原因**：
- 类型名称不正确
- 类型不存在于当前程序集中
- 类型构造函数参数无法解析

**解决方案**：
- 检查类型名称是否正确
- 确保类型存在于当前程序集中
- 确保构造函数参数已正确注册

#### 3. 服务解析失败

**可能原因**：
- 服务未注册
- 服务依赖未注册
- 存在循环依赖

**解决方案**：
- 确保服务已正确注册
- 确保服务依赖已正确注册
- 检查并解决循环依赖

#### 4. 性能问题

**可能原因**：
- 服务生命周期选择不当
- 依赖图过于复杂
- 频繁解析服务

**解决方案**：
- 为频繁使用的服务选择合适的生命周期
- 简化依赖图，减少服务之间的耦合
- 考虑使用缓存，减少重复解析

## 扩展与定制

### 扩展功能

1. **添加自定义生命周期**：在 `GetLifetime` 方法中添加新的生命周期类型
2. **添加自定义解析策略**：扩展 `ResolveServiceAsync` 方法，添加自定义解析逻辑
3. **添加新命令**：在 `Main` 方法中添加新的命令处理逻辑
4. **添加自定义配置选项**：扩展 `IocSettings` 类，添加新的配置选项

### 定制配置

1. **修改默认配置**：编辑 `ioc_aot.setting.json` 文件调整配置
2. **通过环境变量覆盖**：设置相应的环境变量，如 `IOC_DEFAULT_LIFETIME`
3. **运行时配置**：在程序启动时通过代码调整配置

### 集成到其他系统

1. **作为命令行工具**：直接调用可执行文件，通过命令行参数控制
2. **作为库引用**：将核心功能提取为库，供其他系统引用
3. **作为服务**：将功能包装为服务，通过 API 提供
