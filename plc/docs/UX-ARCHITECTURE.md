# PLC·AIOT 控制台 — 用户体验架构（UX Architecture）

> 版本：UX v1 · 重组于架构文档 V9 之后
> 角色：用户体验架构师（ArchitectUX）
> 目标：以「任务心智模型」重组信息架构，消除跨页钻取断点，让运营/分析/治理三类用户都能在 ≤3 次操作内抵达目标。

---

## 1. 现状断点诊断（Why we redesign）

| # | 断点 | 用户感知 | 根因 |
|---|------|----------|------|
| B1 | 导航扁平无分组、8 项挤一列 | 「这一坨都是什么？找不到重点」 | 按数据类型而非用户任务组织 |
| B2 | 社媒/协作页此前要求并入却**从未接入** | 导航承诺的入口缺位，预期落空 | 上一轮任务被中断、未落地 |
| B3 | 地图点位只能悬停、不可点 | 「看到园区点却进不去设备」 | 无点击事件 → 抽屉 |
| B4 | 驾驶舱活动流不可点 | 「这条告警我想看设备，却要自己去找」 | 列表项无行为 |
| B5 | 告警行无设备入口 | 「确认告警后还得去设备页手动搜」 | 行操作缺 openDevice |
| B6 | 通知中心不可点 | 「点通知没反应」 | 静态 `<li>` 无处理器 |
| B7 | 抽屉「地图」tab 是死胡同 | 「说去地图却没按钮」 | 缺跳转动作 |
| B8 | 刷新永远回到驾驶舱 | 「我刚在设备页，一刷新没了」 | 无 hash 深链、无状态恢复 |
| B9 | 搜索一输入就硬跳设备页、无结果数/空态 | 「我只是想看看，结果被拽走」 | 搜索强制跳转 + 无反馈 |
| B10 | 无「未决告警处置」主任务入口 | 「12 条告警藏在一行里，不显眼」 | 缺少 primary task entry |

**结论**：问题不在视觉，而在**信息架构与交互连续性**。视觉系统（DESIGN.md）已达标，需补的是「导航分组 + 跨页上下文 + 深链」。

---

## 2. 目标信息架构（Target IA）

按**用户任务心智**而非数据类型重新分组，把 10 个目的地收束为 3 个清晰簇：

```
PLC·AIOT 控制台
├─ 运营监控  (Operate)  ← 日常值守主路径
│   ├─ 🛰️ 驾驶舱      （首页 / 总览）
│   ├─ 🏭 设备        （资产清单 + 抽屉详情）
│   ├─ 🔔 告警        （FaultEvent 全生命周期，角标=未决数）
│   ├─ 📡 实时看板    （PLC 3D 结构透视）
│   └─ 🗺️ 地图        （全球分布 + 园区钻取）
├─ 分析洞察  (Analyze) ← 横向分析 / 协作
│   ├─ 📊 统计        （吞吐 / OEE / 趋势）
│   ├─ 📣 社媒矩阵    （多平台声量，内网可见）
│   └─ 📋 团队协作    （Notion 风格任务看板）
└─ 系统治理  (Govern) ← 平台 / 管理
    ├─ ⚙️ 系统        （服务健康 / 资源 / 边缘链路）
    └─ 🧩 后端管理    （插件 / 用户 / 主题路由 / 连接器）
```

**设计决策**
- 分组上限 5 项，符合「7±2」短期记忆；主路径（运营监控）置顶。
- 社媒/协作归入「分析洞察」，与日常值守解耦，避免运营人员被无关信息打扰。
- 移除营销落地页（内网场景不需要获客页）。

## 3. 导航与状态模型

### 3.1 导航组件
- **侧边栏（≥1024px 常驻）**：分组标题 `+` 图标链接；当前项左侧 3px 天蓝条 + 渐变底。
- **移动端（<1024px）**：侧栏变抽屉（汉堡唤出）+ 顶部横向滚动胶囊导航，避免层级丢失。
- **告警角标**：动态读取 `DATA.alarms` 未决数，确认/解决后实时更新（修复 B6 静态值）。

### 3.2 深链与状态恢复（修复 B8）
- 路由即 `location.hash`：`#devices`、`#map/ZZ-A2-07`。
- `navigate(page, deviceId)`：更新 hash（replaceState，不触发冗余 hashchange）→ `htmx.ajax` 换片。
- `hashchange` 监听支持浏览器前进/后退；`boot()` 解析初始 hash 恢复页面与上下文。
- **跨页上下文对象 `ctx`**：`{ deviceId, alarmFilter }`，在导航间携带，落地到目标页（如从通知跳告警并预置「活跃」筛选）。

### 3.3 全局设备抽屉（跨页钻取核心）
`openDevice(id)` 是唯一的设备详情入口，**任何页面**均可调用（地图点、活动流条目、告警行、通知项、搜索结果）。抽屉为全局浮层（`role=dialog`），关闭即返回原页，上下文不丢。

## 4. 四条关键用户流（修复后闭环）

### 流 A · 告警处置（修复 B5/B6/B7）
```
通知铃 → 点通知项(带 data-dev) → 打开设备抽屉(信息)
       → 「地图」tab → [在地图中查看 →] 跳地图页并自动高亮该设备
       └─ 或回告警页：点「查看」→ 打开设备抽屉 → 「确认/解决」→ 角标实时 -1
```

### 流 B · 设备定位（修复 B3/B4）
```
地图 → 点园区点 → 设备抽屉(信息) → 「操作/指令」tab 下发命令
驾驶舱 → 点活动流条目 → 设备抽屉（同设备）
```

### 流 C · 数据分析 → 行动
```
统计 → 社媒矩阵 / 团队协作 → 协作任务表点「关联设备」→ 设备抽屉
```

### 流 D · 搜索（修复 B9）
```
顶栏输入 → 下拉实时显示命中设备(最多6) + 结果数/空态 → 点结果 = 设备抽屉（不跳页）
         → 「查看全部」= 跳设备页并保持筛选
```

## 6. 体验原则（后续迭代守则）

1. **三层操作上限**：驾驶舱 → 模块 → 抽屉 Tab，禁止更深的嵌套。
2. **单一设备入口**：所有「看设备」都走 `openDevice`，禁止各自造弹窗。
3. **状态可恢复**：任何深层位置都能用 URL 分享/刷新还原。
4. **反馈即时的**：筛选/确认/搜索都有可见结果数或状态变化，不静默。
5. **任务导向而非数据导向**：导航按「我要做什么」组织，而非「有什么数据」。
6. **移动优先**：窄屏不丢功能，仅改变导航形态（抽屉/胶囊）。
