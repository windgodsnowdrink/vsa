## ADR-109：PluginManager + ALC 热插拔（边缘域）

- **Status**：Deferred（边缘域，不在 SaaS 控制面 plc-saas 范围 —— 见 Decision ④；归入边缘宿主工作流，SaaS P1 不纳管）
- **Background**：根目录协议驱动为 File-based 空壳；真实驱动在 `samples/PlcAiot.Stability` 实现 `IDeviceProtocol`/`DeviceCatalog`/`DeviceCapabilities`，但未接回根驱动层，与 V9 §1.12 统一契约脱节。
- **Decision**：
  1. 所有协议驱动收敛到 `IDeviceProtocol`（消除双轨）。
  2. `PluginManager` 用 `AssemblyLoadContext`（DotNetCorePlugins）在**边缘 JIT 宿主**加载 `plugins/` 目录驱动，支持卸载/热重载。
  3. NativeAOT 边缘宿主（`edge-aot-host.cs`）发固定驱动集 —— ALC 与 NativeAOT 不兼容，文档固化此权衡。
  4. SaaS 控制面 `plc-saas` 不涉及运行时插件加载。
- **Consequences**：
  - 正面：驱动可热插拔、契约统一。
  - 负面：驱动收敛工作量；ALC 仅 JIT 宿主可用。
- **Related**：V9 §1.12、ADR-101。
> **实现状态（2026-08-16）**：属**边缘 JIT 宿主**（`samples/PlcAiot.Stability`）而非 `plc-saas` 控制面，故不在 SaaS P1 范围内。SaaS 侧无需运行时插件加载（ADR-109 ④）。

## ADR-110：Wolverine Outbox 采用时机

- **Status**：Deferred → P2（沿用 ADR-102 自建事务 Outbox + MeteringAgent 轮询；Wolverine 采用推迟至 P2/Later，触发条件"接通真实 EMQX"（ADR-113）已满足，但收益未到刚需）
- **Background**：`plc-saas` 已用 Mediator(MIT) + 自建事务 Outbox（ADR-102），测试通过。
- **Decision**：MVP 保留自建 Outbox；当接通真实 EMQX 传输（ADR-113）或需成熟 inbox/调度时，引入 Wolverine 的 EF Core 事务 Outbox 替代轮询 Agent；CQRS 派发仍用 Mediator。
- **Consequences**：
  - 正面：降低 preview 期依赖面，延后 Wolverine 收益至确需时。
  - 负面：手搓轮询 Agent 长期维护成本。
- **Related**：ADR-102、ADR-105、ADR-113。
> **实现状态（2026-08-16）**：ADR-113（真实 EMQX 传输）已落地，触发条件“接通真实 EMQX 传输”已满足；但本 ADR 决策仍“MVP 保留自建 Outbox”，故 Wolverine 采用待架构师 ratify。当前 `plc-saas` 沿用自建事务 Outbox + `MeteringAgent` 轮询消费，运行正常（校验 6/6 通过）。

## ADR-111：YARP 网关 / WAF

- **Status**：Deferred → P2（内网免费部署 ADR-108，YARP/WAF 仅公网暴露时需；归入 P2/Later）
- **Background**：多租户 SaaS 需统一入口（路由/TLS/全局限流接配额 429）；当前无网关；内网免费部署（ADR-108）。
- **Decision**：V1 内网用轻量 YARP 前置（路由 + TLS + 全局限流中间件）；WAF(ModSecurity) 推迟至公网暴露；若已有 nginx/traefik 入口则可省略 YARP。
- **Consequences**：
  - 正面：统一入口 + 限流闭环。
  - 负面：内网 WAF 非必须，增加一跳延迟。
- **Related**：ADR-108。

## ADR-112：MEAI + MCP + Qdrant

- **Status**：Accepted（P1 已落地，详见 `docs/ADR-112-implementation.md`）
- **Background**：`AI.cs` 空壳；AIOT 品牌需 AI 故障诊断 / RAG。
- **Decision**：MEAI 作 LLM 抽象；暴露设备/故障/遥测为 **MCP Server**（`tid` 作用域隔离）；Qdrant 存故障模式向量（租户分区 collection）；`AiAssistant` feature flag 门控。
- **Consequences**：
  - 正面：差异化能力，外部 AI Agent 可安全问诊。
  - 负面：非 MVP 核心，Phase 5。
- **Related**：ADR-103（隔离）。

## ADR-113：真实 MQTT/EMQX 客户端（数据平面关键路径）

- **Status**：Accepted（V1-now 已实现，详见 `docs/ADR-113-implementation.md`）
- **Background**：`MQTT.cs` 空壳；ADR-107 已定 EMQX JWT+ACL 租户隔离但无桥；`plc-saas` 的 `TelemetryIngested` 无订阅者。
- **Decision**：
  1. **主路径**：EMQX 规则引擎 → `plc-saas` HTTPS 摄取端点（`POST /api/v1/ingest/telemetry`、`/ingest/fault`），无状态易扩展。
  2. **边缘中继（可选）**：`MQTTnet` 订阅租户主题聚合后上行。
  3. 摄取：校验 `tid` → 映射 `Device`（全局唯一）→ Mediator 事件 → Outbox → 写 InfluxDB(遥测)+PG(故障) → SignalR `/hubs/faults` 推送。
  4. 隔离沿用 ADR-107（EMQX JWT `tid` + ACL）+ 控制面 `TenantMiddleware`/EF 过滤器/RLS。
- **Consequences**：
  - 正面：数据平面打通，SaaS 才有实时数据。
  - 负面：依赖 EMQX 部署拓扑。
- **Related**：ADR-107、ADR-105、ADR-103。⭐ 优先级 P0。
