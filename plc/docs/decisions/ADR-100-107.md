## ADR-100：.NET 11 SDK 版本钉选

- **Status**：Accepted（2026-08-15）
- **Background**：Phase 0 锁定 .NET 11 Preview，SDK `11.0.100-preview.6`。现有 `global.json` 写 `"version": "11.0.100"` + `latestFeature`，会漂移且未钉到 preview.6。
- **Decision**：`global.json` 显式钉 `11.0.100-preview.6`，`rollForward: latestPatch`，`allowPrerelease: true`。CI 锁该版本。
- **Consequences**：
  - 正面：可复现构建；与团队锁定一致。
  - 负面：preview 期 API 可能变（GA 前）；需上线前迁 .NET 11 GA。
- **Related**：ADR-102（依赖 preview 期库）。

## ADR-101：VSA 端点组织方式

- **Status**：Accepted（2026-08-15）
- **Background**：需 VSA 切片 + File-based App。Carter 依赖程序集扫描，与 File-based 单文件模型冲突。
- **Decision**：Minimal API 内联端点 + File-based `#include "infra.cs"` 共享基础设施；不引入 Carter。
- **Consequences**：
  - 正面：每切片自包含，零程序集扫描，契合 File-based + VSA。
  - 负面：共享设施靠 `#include`，需约定 infra 文件职责。
- **Related**：ADR-102。

## ADR-102：CQRS 进程内派发与 Outbox

- **Status**：Accepted（2026-08-15）
- **Background**：架构 V9 已定 CQRS 用 Mediator(MIT)；MediatR 转商业许可不可用。
- **Decision**：CQRS 派发用 Mediator(martinothamar, MIT) 源码生成（`[EventHandler]` 编译期注册）；MVP 自建事务 Outbox 表（不引 Wolverine，降低 preview 期依赖面）。
- **Consequences**：
  - 正面：零反射、NativeAOT 友好、MIT 合规；Outbox 自建减少外部依赖与 preview 兼容风险。
  - 负面：自建 Outbox 需写轮询 Agent；Wolverine 的成熟可靠性延后获得。
- **Related**：ADR-100、ADR-105。

## ADR-103：多租户数据隔离策略

- **Status**：Accepted（2026-08-15）
- **Background**：Phase 0 决策共享 DB + TenantId 行级隔离；需落地机制防越权。
- **Decision**：共享 PostgreSQL + 每租户表 `TenantId` 列 + EF Core 全局查询过滤器（`ITenantEntity` 标记）+ `SaveChangesInterceptor` 写时盖戳 + PostgreSQL RLS 兜底。
- **Consequences**：
  - 正面：逻辑隔离、单迁移、运维最低；框架级而非纪律级防越权；RLS 纵深防御。
  - 负面：全局过滤器可被 `IgnoreQueryFilters()` 绕过（已被拦截器+RLS+审计缓解）；超大租户未来需 Schema/DB 隔离（Later）。
- **Related**：ADR-104、ADR-107。

## ADR-104：多租户认证方案

- **Status**：Accepted（2026-08-15）
- **Background**：SaaS 需用户/角色管理与租户维度认证。
- **Decision**：ASP.NET Core Identity（用户/角色存储）+ JWT Bearer；access 15min / refresh 7d；JWT 含 `tid` 租户声明；`ApplicationUser : IdentityUser` 带 `TenantId`。`dotnet user-jwts`（.NET 11 支持 File-based）本地发测试令牌。
- **Consequences**：
  - 正面：官方栈零额外依赖；租户维度随 `tid` 声明贯穿认证与数据隔离。
  - 负面：企业 SSO / LDAP / 外部目录（OIDC）列入 Later；租户内基础四角色（管理员 / 分析师 / 值守 / 设备工程师）本期建设，分析师强制只读无写入口。
- **Related**：ADR-103、ADR-107。

## ADR-105：告警实时性保障

- **Status**：Accepted（2026-08-15）
- **Background**：PRD 流 A 要求告警确认后角标实时更新；CQRS 最终一致读副本可能滞后。
- **Decision**：告警热路径 = 命令成功 → 域内事件 → 读模型同 UoW 同步投影 + SignalR Hub 直推前端；PostgreSQL 读副本仅承载统计/OEE 等分析类最终一致查询。
- **Consequences**：
  - 正面：满足北极星指标（未决告警闭环率）与流 A 实时性；分析查询仍可横向扩展。
  - 负面：SignalR 引入实时通道；热路径与主写库耦合（强一致必要代价）。
- **Related**：ADR-102、ADR-103。

## ADR-106：图标库锁定（P0 硬约束）

- **Status**：Accepted（2026-08-15）
- **Background**：P0 绝对规则：Spec 必须锁定一套 SVG 图标库，禁止 emoji 图标方案；API/架构文档禁用 emoji。
- **Decision**：锁定 **Lucide（ISC，24×24，2px 描边，currentColor）** 为唯一 SVG 图标源；全站禁 emoji。前端用雪碧图 `wwwroot/css/icons.svg` 或 `@lucide/...` 包，与 DESIGN.md §10 / SaaS-PRD.md §9.1（SSOT=Lucide）对齐。
- **Consequences**：
  - 正面：管理/仪表盘/租户/账单图标最全，与科技天蓝玻璃态一致；MIT 合规；服务端无关。
  - 负面：仅锁一套不混用，需全站替换既有 emoji 占位。
- **Related**：无（跨职能约束）。

## ADR-107：MQTT 多租户隔离（九段主题无租户段）

- **Status**：Accepted（2026-08-15）
- **Background**：既有九段 MQTT 主题 `devices/{continent}/{country}/{province}/{city}/{district}/{line}/{batch}/{deviceId}/{type}` 无租户段（§17.8/§17.9）。PM 提出多租户下需隔离 MQTT 流量。
- **Options**：
  - A. 主题加 `t/{tenantId}` 前缀 → 打断九段体系，需改边缘桥接/EMQX 路由/前端订阅/域模型 `TopicPath`。
  - B. 租户级 MQTT 凭据 + Broker ACL，九段主题不变 → 隔离在 Broker 层强制，前端/边缘零改造。
- **Decision**：采用 **方案 B**。每个 MQTT 连接携带租户身份：浏览器用用户 JWT 派生的短时 MQTT 凭据（含 `tid`）；边缘网关 onboard 时获租户作用域凭据（存 Device 注册表，可轮换）；EMQX 启用 JWT 认证 + HTTP AuthZ ACL，按连接 `tid` 经 `Tenant`/`Device` 注册表映射其名下 deviceId 集合为允许主题过滤器 `devices/+/+/+/+/+/+/{deviceId}/#`。因 `DeviceId` 全局唯一，无租户段亦可完全隔离租户。
- **Consequences**：
  - 正面：不打断 §17.8/§17.9；Broker 层强制隔离，无法绕过；主题树干净。
  - 负面：需 EMQX JWT auth + HTTP AuthZ 与注册表联动；边缘凭据生命周期与轮换需设计；假设单边缘站点单租户（多租户边缘列入 Later）。
- **Related**：ADR-103、ADR-104、ADR-105。

## ADR-108：Billing MVP = 计量 + 配额强制，不计费（内网免费）

- **Status**：Accepted（2026-08-16）
- **Background**：用户 2026-08-16 裁定「套餐 / 配额 / 用量计量上线只计量不产生费用，为内网免费使用」。Phase 0 要求本期完整建设 Tenant / Identity / Billing 三大上下文，故 Billing 仍需落地，但商业化（收费）不在本期。
- **Decision**：Billing 上下文 MVP 落地「套餐档（用于配额差异化，无价格字段）+ 用量计量（设备数 / 遥测点）+ 配额强制（超限提醒 + 限流）」；**不产出账单、不出账、不接支付网关、不引入货币字段**。订阅生命周期状态机仅保留运营态（Active + 平台运营可暂停 / 恢复），财务「逾期→付费」转换延后至计费上线（Later）。MRR / NRR 商业北极星本期不适用，以内网采用指标（活跃租户数 / 每租户设备数 / TTFD）替代。
- **Consequences**：
  - 正面：保留完整计量与配额能力，未来计费上线零改造；降低 MVP 范围与合规负担；内网免费使用边界清晰。
  - 负面：无收入指标；套餐档仅作配额差异化无价格；计费上线时需补出账 / 支付 / 发票链路与货币字段迁移。
- **Related**：ADR-103、ADR-104、ADR-107；SaaS-PRD §6 / §10；SaaS-Spec §2 / §3 / §9(AC-10) / §10。
