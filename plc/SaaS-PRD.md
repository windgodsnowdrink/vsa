## 1. SaaS 化背景与核心问题（Why）

现有 V1 为**单租户内网控制台**。PRD v1.0 §1.4 明确将「多租户 / 计费」列为 Non-goal；§11 风险清单已标注「暂无 RBAC」「多角色数据越权风险」。

要对**外部中小制造企业**作为 SaaS 售卖，必须补齐四块能力：

1. **租户开通与隔离**：当前无租户概念，所有数据混在一库。需支持自助开通 + 行级隔离 + 边缘主机按租户授信。
2. **身份与权限**：无多租户登录与角色模型，跨租户越权风险高。需租户内角色（管理员 / 分析师 / 值守 / 设备工程师）与平台运营超管。
3. **计费与配额**：无订阅、配额、账单，无法商业化。需套餐、按设备 + 遥测配额、用量计量、生命周期状态机。
4. **边缘 + 云一体化复用**：既有边缘链路（SQLite / Mosquitto / Datasync + 九段 MQTT 主题）是差异化资产，但需把**租户维度**引入消息层与边缘主机，否则隔离只在中心库成立、边缘侧仍混流。

## 3. 我们的差异化（为什么选我们）

1. **边缘自治 + 中心汇聚双层**：既有 SQLite + Mosquitto + Datasync 边缘链路与九段 MQTT 主题，弱网离线优先、恢复自动收敛。竞品中只有 Samsara 强硬件捆绑、Azure 纯云无离线主权、ThingsBoard 需自管运维。
2. **标准 SaaS 隔离、零 DevOps 负担**：共享库 + TenantId 行级隔离，比 ThingsBoard 自托管省运维，比 Azure 保留数据主权选项。
3. **PLC 域原生、开箱即用**：预置设备生命周期、告警 FaultEvent 全生命周期、OEE、3D 机架透视、全球分布地图、未决告警主任务入口——竞品多为空平台需自建。
4. **透明、无锁计费**：无 3 年锁、无硬件捆绑；按设备 + 遥测配额，设备数可随业务上/下调整；试用→付费平滑过渡。
5. **中文 / 国产化内网友好**：本地化 vendor、暗色玻璃设计系统，贴合国内厂长/运维心智。

## 4. 扩展用户画像（角色 / 场景 / 诉求）

| 角色 | 场景 | 诉求 |
|------|------|------|
| **租户管理员（Tenant Admin）** | 新制造企业在控制台自助开通组织；添加同事、注册产线设备、选套餐、看用量与账单 | 开通快、隔离可信、用量与账单清晰、能随时增减设备 |
| **平台运营（Platform Operator / 超管）** | 在运营后台开通/暂停租户、配置套餐与配额策略、看 MRR 与租户健康、处理欠费 | 全局可视、开通/暂停一键、计费策略可调、异常租户可干预 |
| **租户内分析师（Tenant Analyst）** | 看统计/OEE/社媒/协作，关联设备下钻，但**只读不下发指令** | 数据完整、限本租户、无需写权限 |
| **租户内运营值守（Tenant Operator）** | 既有 7×24 告警值守，但设备范围限定在本租户 | 与 V1 一致体验，但绝看不到别家设备 |
| **租户内设备工程师（Tenant Device Eng）** | 注册设备、下发指令、看心跳日志，限本租户 | 设备详情完整、指令可追溯、跨租户不可见 |

> 既有「运维主管/厂长（Govern）」在 SaaS 下映射为**租户管理员或其授权治理角色**；平台级治理（插件/连接器/主题路由）收归平台运营。

## 5. SaaS 增量功能清单（标准用户故事）

1. **作为潜在租户**，我希望在落地页填写企业信息并自助开通组织，以便数分钟内获得独立租户与登录入口。
2. **作为租户管理员**，我希望开通后系统自动为我预置空租户（TenantId、配额、默认管理员账号），以便立即开始添加设备。
3. **作为任意租户用户**，我希望用「租户标识 + 账号」登录且只能看到本租户数据，以便数据隔离可信。
4. **作为租户管理员**，我希望在租户内创建角色（管理员/分析师/值守/设备工程师）并分配成员，以便按职责授权、杜绝越权。
5. **作为平台运营**，我希望在运营后台查看全部租户、开通/暂停、看 MRR 与用量排行，以便掌控 SaaS 全局健康。
6. **作为租户管理员**，我希望选择套餐（试用/标准/企业）并看到设备数与遥测配额，以便按规模付费。
7. **作为租户管理员**，我希望实时看到本租户设备数、本月遥测用量与配额剩余，以便在超限前扩容。
8. **作为计费系统**，我希望在租户用量达到配额阈值时触发提醒与限流策略，以便保护平台并引导扩容。
9. **作为租户**，我希望经历「试用 → 付费 → 逾期 → 暂停/恢复」清晰生命周期，以便在宽限期内自助续费不影响数据。
10. **作为租户管理员**，我希望在「账户」区查看账单明细与发票，以便财务对账（MVP 可后台生成、后续接支付网关）。
11. **作为平台运营**，我希望审计全部租户的关键操作（开通/套餐变更/暂停），以便合规与排障。
12. **作为租户用户**，我希望首次登录经引导完成「创建/加入租户 → 注册首台设备」路径，以便快速产生价值（Time-to-First-Device）。

公式：`Score = (Reach × Impact × Confidence) / Effort`；Reach 1–10（每季度受影响租户数），Impact 0.25/0.5/1/2/3，Confidence 50/80/100%，Effort 1–10（人月）。

| 功能 | Reach | Impact | Confidence | Effort | Score | MVP？ |
|------|-------|--------|------------|--------|-------|-------|
| 租户开通与自动预置（Tenant 上下文） | 10 | 3 | 100% | 8 | **3.75** | ✅ MVP |
| 租户隔离强制（TenantId 行级 + MQTT 层隔离） | 10 | 3 | 100% | 8 | **3.75** | ✅ MVP |
| 多租户登录与租户内角色（Identity 上下文） | 10 | 2 | 100% | 6 | **3.33** | ✅ MVP |
| 套餐与配额模型 + 用量计量（Billing 上下文） | 8 | 2 | 80% | 8 | 1.60 | 同版本切片 |
| 订阅生命周期状态机（试用→付费→逾期→暂停） | 8 | 2 | 80% | 5 | 2.56 | 同版本切片 |
| 租户管理控制台（用量/套餐/成员/账单） | 7 | 2 | 90% | 5 | 2.52 | 同版本切片 |
| 支付/账单集成（接支付网关） | 6 | 2 | 60% | 6 | 1.20 | Backlog（MVP 后台出账） |
| 审计日志（租户内 + 平台） | 5 | 1 | 80% | 4 | 1.00 | Backlog |
| 平台运营后台（超管） | 3 | 2 | 90% | 6 | 0.90 | 同版本切片（最小可用） |
| SSO / 企业目录对接 | 3 | 1 | 70% | 5 | 0.42 | Backlog（企业版） |

### MVP 范围（本期必跑通的核心切片）
1. **租户开通与自动预置**
2. **租户隔离强制（中心库 + 边缘/MQTT 层）**
3. **多租户登录与租户内角色**

> 说明：Phase 0 决策要求本期完整建设 Tenant / Identity / Billing 三大上下文，故「套餐配额、订阅生命周期、租户管理控制台、平台运营后台最小可用」作为**同一发布内的后续垂直切片**（优先级紧随 MVP 前三），不进入 Backlog；仅支付网关、审计、SSO 进入 Backlog。

## 7. 验收标准（Given / When / Then）

- **G1** Given 访客在落地页提交开通表单，When 通过校验，Then 系统在 5 分钟内创建租户记录、预置 TenantId 与默认管理员、返回独立登录入口。
- **G2** Given 租户 A 与租户 B 均有设备，When 租户 A 用户查询设备列表，Then 返回结果仅含 TenantId=A 的数据，且 API 响应头携带租户上下文标识。
- **G3** Given 租户 A 用户尝试访问带租户 B 设备 ID 的 URL，When 服务端校验，Then 返回 403 且不在响应体泄露 B 的任何字段。
- **G4** Given 分析师角色登录，When 进入设备「指令」Tab，Then 该 Tab 不可交互（无写权限入口），仅只读呈现。
- **G5** Given 租户用量达配额 90%，When 系统计量任务运行，Then 向租户管理员推送提醒且记录 `quota_threshold_reached` 事件。
- **G6** Given 试用租户逾期 7 天未付费，When 生命周期任务执行，Then 租户置为「暂停」，保留数据，登录提示续费入口。
- **G7** Given 平台运营在后台暂停某租户，When 该租户用户请求，Then 返回暂停态提示且核心读写被拒（读可降级为只读快照）。

## 8. 边界条件

- **空状态**：新租户无设备 → 控制台引导「注册首台设备」而非空白报错。
- **隔离失败兜底**：若 TenantId 缺失的请求到达写命令，统一在中间件层拒绝（不落库）。
- **配额超限**：超过配额的设备注册/遥测写入按策略限流或计入超额账单，而非静默丢弃。
- **并发开通**：两租户同时开通同名子域 → 子域唯一性校验失败并提示换名。
- **离线/弱网**：边缘主机断网时本地 SQLite 落库，恢复后经 Datasync 按租户增量回推中心，冲突按既定策略收敛。
- **权限拒绝**：跨租户或无角色访问 → 403 + 审计记录，前端引导联系租户管理员。

### 设计约束（移交设计师，遵守 P0 规则）

### 9.1 设计对齐结论（设计师已确认，DESIGN.md §10 为 SSOT）
> 设计师基于上述 6 条约束产出 SaaS 后台布局与组件草案，并修正 DESIGN.md §10。以下为已确认结论，纳入产品规格 SSOT，待三文档交叉验证统一收口。

- **单品牌（落实 P0 禁第二主色 / 禁紫→粉）**：删除原「每租户色相」与「紫色企业档」提案；租户身份用「名称文字 + 组织标（--tenant-dot 统一品牌蓝）」表达，套餐档用 `.badge.info` 以文字区分 免费/专业/商业/企业，不按档位上色。

- **租户管理员「账户」4 页**：用量概览（`#account/usage`）、套餐与订阅（`#account/plan`）、成员管理（`#account/members`）、账单与发票（`#account/billing`）。

- **可达性**：状态「色 + 字」双信号；配额 meter 加 `role="progressbar"` + `aria-valuenow/max`；切换器/确认弹窗焦点陷入 + Esc；MVP 单品牌（白标列企业版路线图）。

## 10. SaaS 北极星与驱动指标

> 运营北极星（既有，保留）：**未决告警 30 分钟闭环率**（PRD §10.1）。以下为 **SaaS 商业层新增指标**，基线均为拟定，需在首个外部租户上线后 2 周内用真实埋点校准。

### 北极星（North Star）
**月度经常性收入 MRR** —— 直接反映 SaaS 商业化增长核心。
> 拟定基线：上线首月以种子租户校准（标注需埋点）；目标 3 个月内 MRR 转正且月环比 ≥ 15%。
> 健康北极星（辅助）：**净收入留存率 NRR ≥ 100%**（扩展 > 流失），目标 110%+。

### 驱动指标
| 指标 | 说明 | 拟定基线 → 目标 | 校准 |
|------|------|------------------|------|
| 活跃租户数 | 近 30 天有设备遥测或登录的租户 | 需埋点 → 月增 ≥ 8 | 需校准 |
| 每租户设备数 | devices 数 / 租户数（扩展信号） | 需埋点 → 中位 ≥ 15 | 需校准 |
| 试用→付费转化率 | 试用租户转付费占比 | 需埋点 → ≥ 25% | 需校准 |
| 租户月留存率 | 本月活跃且上月活跃占比 | 需埋点 → ≥ 90% | 需校准 |
| 扩展 MRR | 存量租户增设备/升套餐带来增量 | 需埋点 | 需校准 |

### 健康指标
| 指标 | 目标 |
|------|------|
| 开通到首台设备上线时长（Time-to-First-Device） | ≤ 30 分钟 |
| 账单准确率 | 100%（用量计量与出账一致） |
| 配额超限率（未提前提醒即超限） | < 5% |
| 跨租户越权请求拦截率 | 100% |

### SaaS 数据埋点（必埋事件）
| 事件 | 说明 |
|------|------|
| `tenant_created` / `tenant_provisioned` | 租户开通与预置完成 |
| `tenant_first_device_online` | 首台设备上线（TTFD 计算） |
| `user_login`（含 tenant_id / role） | 多租户登录 |
| `subscription_started` / `subscription_upgraded` / `subscription_downgraded` / `subscription_suspended` | 订阅生命周期 |
| `quota_threshold_reached` / `quota_exceeded` | 配额 |
| `payment_completed` | 付费成功（接网关后） |
| `tenant_churned`（30 天无活动） | 流失 |

## 11. 市场空白与机会点

1. **透明、无锁计费**：Samsara 的 3 年锁与隐藏终止费、Tulip 年付门槛，把中小制造挡在门外。我们用「无长期锁 + 按设备/遥测配额 + 可上可下」切这个空白。
2. **低门槛 SMB 入口**：ThingWorx（$100k+/年）、Tulip（$12k/年起）对中端过高。我们设 ¥0 试用 + 低价标准版，降低首单。
3. **边缘离线主权 + 云汇聚**：Azure IoT Central 纯云无本地主权；Samsara 靠自有硬件。我们既有边缘链路（SQLite/Mosquitto/Datasync）天然支持弱网离线，是差异化卖点。
4. **PLC 域原生开箱**：ThingsBoard/Ubidots 是空平台，OEE/告警/3D 机架需自建。我们预置 PLC 监控域，缩短 Time-to-Value。
5. **租户内 RBAC 成熟度**：ThingsBoard CE 无 RBAC，多数竞品角色粗糙。我们 Identity 上下文内建管理员/分析师/值守/设备工程师四角色。
6. **中文内网友好**：国产化、本地化 vendor、暗色玻璃设计，贴合国内厂长运维心智，避开纯英文云控制台门槛。

## 12. 开放问题与需对齐项

1. **MQTT 主题租户维度（关键，待架构师确认）**：九段主题 `devices/{continent}/{country}/.../{deviceId}/{type}` 当前无租户段。需确认隔离方式：
   - 方案 A：主题前缀加 `t/{tenantId}/devices/...`；
   - 方案 B：租户级 MQTT 凭据 + Broker ACL（EMQX）按租户授权，主题结构不变。
   - 倾向 B（不改既有九段语义、权限由 Broker 管控），但需架构师评估边缘 Mosquitto bridge 改造量。
2. **配额计量来源**：按「设备数」还是「遥测消息数/点」或二者组合？建议设备数（显性、易理解）+ 遥测点包（防刷），需结合边际成本校准单价。
3. **支付集成**：MVP 是否接支付网关（如微信支付/Stripe），还是后台人工出账？建议 MVP 后台出账 + 自助套餐切换，支付网关进 Backlog。
4. **白标范围**：MVP 单品牌（沿用科技天蓝）；租户自定义 Logo/域名进企业版。
5. **物理隔离**：共享库行级为默认；企业版是否需要独立库/私有部署？进路线图。
