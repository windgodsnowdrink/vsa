# Skills文件夹结构改造计划

## 项目目标

将skills文件夹下的每个技术文件夹按照指定的目录结构进行改造，包括添加元数据文件、配置文件、详细注释和示例文档。

## 目录结构规范

每个技术文件夹需要遵循以下结构：

```
/skills/xxx/
├── index.yaml                   # 第一层：元数据索引说明
├── SKILL.md                    # 第二层：核心指令入口点
├── reference/                  # 第三层：引用文件（按需加载）
│   ├── README.md           # 创建和配置说明
│   ├── examples.md           # 调用和测试说明
└── scripts/                    # 脚本和工具
│   ├── xxx.cs          # net10单文件执行脚本
│   ├── xxx.settings.json          # net10配置文件
│   ├── xxx.run.json          # net10运行环境
│   ├── xxx_test.cs     # net10单文件测试脚本
└── data/                    # 可选：数据
    ├── xxx.json          # json数据文件
```

## 实施步骤

### 1. 文件夹结构创建

* 遍历skills下的所有技术文件夹

* 为每个文件夹创建reference/和data/子文件夹

* 确保scripts/子文件夹存在

### 2. 文件改造

#### 2.1 .cs文件改造

* 为每个.cs文件添加`#!/usr/bin/env dotnet`开头行

* 添加详细的中文注释和说明

* 包括：

  * 文件概述

  * 功能说明

  * 核心类和方法注释

  * 使用示例

#### 2.2 \_test.cs文件改造

* 添加详细的中文注释和说明

* 包括：

  * 测试目的

  * 测试用例说明

  * 测试方法注释

  * 预期结果

#### 2.3 配置文件创建

* 为每个.cs文件创建对应的settings.json文件

* 为每个.cs文件创建对应的run.json文件

* 配置文件包含必要的运行时配置和环境设置

### 3. 文档创建

#### 3.1 reference/README.md

* 每个技术文件夹的创建和配置说明

* 技术背景和用途

* 安装和依赖说明

#### 3.2 reference/examples.md

* 调用和测试说明

* 代码示例

* 使用场景

* 常见问题和解决方案

### 4. 数据文件创建

* 为需要mock数据的技术创建json数据文件

* 数据文件存放在data/文件夹下

## 技术要点

1. **批量处理**：使用脚本自动化处理大量文件
2. **统一规范**：确保所有文件遵循相同的注释和格式规范
3. **中文注释**：所有注释和文档使用中文
4. **配置文件**：为每个脚本创建独立的配置文件
5. **示例文档**：提供详细的使用示例和说明

## 预期成果

* 所有技术文件夹遵循统一的目录结构

* 所有.cs文件包含详细的中文注释

* 每个脚本都有对应的配置文件

* 提供完善的文档和示例

* 便于后续维护和扩展

## 实施顺序

1. 先处理少量技术文件夹作为试点
2. 验证方案可行性后，批量处理所有文件夹
3. 最后进行整体检查和调整
